> 审查日期：2026-08-26
> 审查范围：backend/（FastAPI 后端）、frontend/（Vite+Vue3）、docs/、仓库配置

## 二、P0 详解

### 1. 异步路由中的同步阻塞调用（最严重）

**现状**
- `backend/agent.py::_chat`（第 161 行）使用同步客户端：

```python
with httpx.Client(timeout=timeout) as client:   # ← 同步阻塞
    resp = client.post(url, json=payload, headers=headers)
```

- `chat()`（第 561 行，`def` 同步）及其派生的 `summarize_note` / `organize_notes` / `recommend_path` / `optimize_algorithm` / `describe_files_batch` / `generate_study_plan` 等全部走这条同步路径。
- `routers/agent.py` 中 `api_agent_chat`（第 349 行）、`api_agent_summarize`（第 106 行）等是 `async def` 路由，**直接调用上述同步函数**。
- 唯一正确实现是 `chat_stream`（第 578 行，`async def`，用 `httpx.AsyncClient` 并 `await`）。

**影响**
FastAPI 基于单线程事件循环。在 `async` 路由里跑同步阻塞式 HTTP（且超时长达 90s），会**阻塞整个 loop**——LLM 思考期间，搜索、数据加载、图谱等所有其他请求全部卡住。本地单用户勉强可用，但一旦并发（如边流式对话边搜索）就暴露问题，且长超时期间进程"假死"。

**修复方向（二选一，推荐 A）**
- **A. 把 `_chat` 改为异步版**（最干净，因为路由本就 async）：

```python
async def _chat(messages, *, ...):
    async with httpx.AsyncClient(timeout=timeout) as client:
        resp = await client.post(url, json=payload, headers=headers)
        resp.raise_for_status()
        return _extract_content(resp.json())
```

  注意：DB 读写（`_db.add_message` 等）若移到异步上下文，需保证 SQLite 连接线程/协程安全（见问题 3）。
- **B. 用线程池隔离阻塞调用**（改动最小，但不如 A 彻底）：

```python
from fastapi.concurrency import run_in_threadpool
result = await run_in_threadpool(_chat, messages, ...)
```

  此时 SQLite 全局连接会在 worker 线程被访问，必须配合 `check_same_thread=False`（已有）+ 写锁或每线程连接。

### 2. 明文密钥进入版本库

**现状**
- `routers/agent.py::_DEFAULT_AGENT_CONFIG` 硬编码 `apiKey` 与 `hermesKey`。
- 首次请求 `_get_agent_config()` 把含密钥的 `agentSettings` 写入 `data/user_data.json`。
- 根 `.gitignore` 中有 `!/app/data/user_data.json`（强制跟踪），使该文件带密钥入库。
- README「安全说明」称 "user_data.json 不含敏感信息" —— **已不成立**。

**修复方向**
- 密钥改读环境变量（`os.environ` / `.env`），不写 `user_data.json`、不入库。
- 若必须本地保存，序列化 `agentSettings` 前剔除 `apiKey`/`hermesKey` 字段。
- 迁移用途改由独立导出/导入脚本完成，而非强制 `git add` 该文件。
- 已入库历史中的密钥视为已泄露，应轮换。

## 三、P1 详解

### 3. SQLite 并发写风险

`db.py` 使用单一全局连接 + `check_same_thread=False` + WAL，但**未设 `busy_timeout`**。异步 agent 端点并发 `add_message`/commit 时可能抛 "database is locked"。

```python
# init_db 内补充
_conn.execute("PRAGMA journal_mode=WAL")
_conn.execute("PRAGMA busy_timeout=5000")   # ← 建议新增
_conn.execute("PRAGMA foreign_keys=ON")
```

高并发场景进一步改为每线程连接或加 `threading.Lock` 包裹写操作。

### 4. 文档漂移

| README 声称 | 实际代码 |
|-------------|----------|
| `main.py` 第 506 行 `port=8000` | `main.py` 共 96 行，端口在第 96 行 |
| `build_core.py` 第 14 行 `"ttl": 60` | 实际第 286 行 |
| `build_core.py` 第 15~18 行 `NOTES_DIR` | 实际第 24 行 |
| 默认绑定 `0.0.0.0` | `main.py` 实际 `host="127.0.0.1"` |
| API 一览（仅 11 个） | 实际还有 `/api/agent/*`（config/health/summarize/chat-stream/refresh-all/…）、`/api/typora/*`、`/api/insights` 等数十个 |

**建议**：按现状重写「常用参数配置」与「API 接口一览」，或加脚本自动生成接口清单。

## 四、P2 详解

### 5. 搜索性能

`build_core.search_notes` 每次都执行：

```python
search_text = (name + " " + " ".join(t for _, t in heads) + " " + text).lower()
```

对全量笔记重复小写化与拼串，O(n) 且重复。当前 75 篇无感，但会随笔记增长变慢。

**修复**：在 `build_index` 阶段一次性预计算并缓存小写 `search_blob`（随 `_text` 一并存入 `_cache`），搜索直接复用；同理把 `mtime` 字符串预解析为时间戳，避免 `_score_notes` 等反复 `datetime.strptime`。

### 6. 编辑器探测重复执行

`detect_editors()`（读注册表 + 探测 exe 存在性）在每次冷缓存 `build_index` 都执行（每 60s 一次）。编辑器基本不变。

**修复**：将编辑器探测结果单独缓存（模块级变量或带更长 TTL），不要放进 60s 重建的索引缓存。

### 7. 前端打包未做代码分割

`dist` 主包 `index-*.js` 约 409KB、`index-*.css` 约 94KB。`d3-force`/`d3-zoom` 仅在图谱页使用却打进主包；所有路由未按需加载。

**修复**：用 `defineAsyncComponent` 懒加载 `GraphPage`/`LearningPathPage`/`AgentPage`；图谱相关 `import('d3-force')` 动态引入。对本地 597KB 总体积可接受，但懒加载能显著改善首屏。

### 8. Markdown HTML 安全

`marked@18` 在客户端渲染笔记/LLM 输出 HTML，配合 `utils/safeHtml.js`。请确认对笔记与外链内容做了 sanitize（如 DOMPurify），避免潜在 XSS（本地单用户风险低，但笔记可能含外部脚本）。

### 9. 冗余端点

非流式 `api_agent_chat` 与流式 `api_agent_chat_stream` 并存，前者走阻塞 `chat`。若前端只用流式，建议废弃前者，统一异步路径，缩小维护面。

- **`derive_tags` / `derive_name_tags` 短 ASCII 关键词整词匹配失效**：原实现用默认 `re`（Unicode 模式下 `\w` 含中文），导致 `ssh`/`git`/`tcp`/`vpn` 等 ≤3 字符关键词紧邻中文时识别不到词边界、永远打不上标签——与其"避免 ssh 命中 sshd"的设计意图相悖，却对中文文件名整体失效。已为两处正则加 `re.ASCII` 标志，使 CJK 被视为非词边界：修复后 `ssh` 在 `ssh登录.md` 命中、`sshd服务.md` 仍正确排除。测试 `test_derive_tags_short_ascii_word_boundary` 固化该行为。
