# 📐 运维知识库应用架构文档

> **一句话心法**：内容层（notes/）与应用层（app/）完全解耦，后端扫描磁盘构建内存索引（TTL 60s），前端 SPA 按需拉取 API，AI 对话双后端（Hermes 优先 + pcl 兜底），用户数据和 AI 记忆分别用 JSON 和 SQLite 持久化。

## 一、整体架构图

![架构图](./architecture.mmd)

### 四层模型

| 层 | 组件 | 职责 |
|----|------|------|
| **浏览器层** | Vue3 SPA（Hash 路由 + Pinia + Tailwind） | 页面渲染、状态管理、API 调用 |
| **后端层** | FastAPI（main.py + 5 个 router） | 路由分发、SPA 托管、文件读取、AI 转发 |
| **数据层** | 磁盘文件 + JSON + SQLite | 笔记内容、用户数据、AI 记忆 |
| **AI 层** | Hermes API（优先）+ pcl GLM API（兜底） | 对话、摘要、整理、学习路径推荐 |

### 技术栈

| 层 | 技术 | 版本 |
|----|------|------|
| 前端 | Vue 3 + Vite + Pinia + Tailwind CSS | Vue 3.5 / Vite 8 |
| 后端 | FastAPI + Uvicorn | FastAPI 0.111 |
| 数据 | JSON 文件 + SQLite（WAL 模式） | Python 3.11 |
| AI | Hermes Agent API + pcl GLM-5.2 | OpenAI 兼容协议 |

## 二、数据交互流程

![数据流](./data-flow.mmd)

### 5 个核心场景

| # | 场景 | 请求路径 | 数据流 |
|---|------|----------|--------|
| ① | 首次加载 | `GET /api/data` | build_core 扫描磁盘 → 内存索引 → 返回 JSON |
| ② | 搜索笔记 | `GET /api/search?q=xxx` | 内存索引全文匹配 → 打分排序 → 结果列表 |
| ③ | 阅读笔记 | `GET /api/note/{name}` | 读 .md 文件原文 → 前端 marked 渲染 |
| ④ | AI 对话 | `POST /api/agent/chat` | 取 SQLite 历史 → 调 Hermes → 存新消息 → 返回 |
| ⑤ | 索引刷新 | `POST /api/rebuild` | 清空缓存 → 下次请求自动重新扫描 |

## 五、数据存储机制

### 数据分三层存储

| 数据类型 | 存储位置 | 持久化方式 | 重启后 |
|----------|----------|------------|--------|
| **笔记内容** | `notes/*.md` | 磁盘文件 | ✅ 保留 |
| **PDF 参考** | `references/*.pdf` | 磁盘文件 | ✅ 保留 |
| **用户数据** | `app/data/user_data.json` | JSON 原子写入（tmp→bak→rename） | ✅ 保留 |
| **AI 对话记忆** | `app/data/agent_memory.db` | SQLite WAL 模式 | ✅ 保留 |
| **笔记索引** | 内存 `_cache` | 内存缓存 TTL=60s | ❌ 自动重建 |
| **前端状态** | 浏览器 localStorage | 客户端本地 | ✅ 保留 |

### user_data.json 结构

```json
{
  "favs": ["笔记ID列表"],           // 收藏的笔记
  "read": ["笔记ID列表"],           // 已读标记
  "opens": {"笔记ID": 次数},        // 打开次数
  "collapsed": ["分类名"],          // 折叠的分类
  "searchHist": ["搜索词"],         // 搜索历史
  "agentSettings": {                // AI 配置
    "apiBase": "https://llmapi.pcl.ac.cn/v1",
    "apiKey": "sk-xxx",
    "model": "GLM-5.2",
    "hermesUrl": "http://172.22.40.153:8642/v1",
    "hermesKey": "hermes_sk-xxx",
    "backend": "auto"
  }
}
```

### 原子写入流程（save_user_data）

```
写 user_data.json.tmp → 备份旧版 → .bak → 原子改名替换
```

## 七、AI 对话双后端

### 架构

```
用户消息 → agent.py
              │
              ├─ backend=auto → 先试 Hermes
              │                   ├─ 成功 → 返回 + 存 SQLite
              │                   └─ 失败 → 转 pcl GLM API
              │
              ├─ backend=hermes → 强制走 Hermes
              └─ backend=pcl → 强制走 pcl
```

### Hermes 优先的理由

| 特性 | Hermes Agent | pcl GLM API |
|------|-------------|-------------|
| tool_call | ✅ 自带（能操作终端/文件/记忆） | ❌ 纯对话 |
| 共享记忆 | ✅ 跨会话记忆 | ❌ 仅上下文窗口 |
| 稳定性 | ⚠️ 依赖 gateway 运行 | ✅ 公网 API |
| 用途 | 优先选择 | 兜底保障 |

### 记忆持久化

- 所有对话消息存入 SQLite `messages` 表（不截断，全量保留）
- 发给 LLM 时取**最近 50 条**历史（`_HISTORY_LIMIT = 50`）
- 进程重启后记忆完整保留

## 八、缓存与索引机制

### build_core.py 内存缓存

```python
_cache = {"payload": None, "ts": 0, "ttl": 60}
```

| 场景 | 行为 |
|------|------|
| 首次请求 | 扫描磁盘 → 构建索引 → 存内存 |
| 60 秒内请求 | 直接返回缓存（不碰磁盘） |
| 60 秒后请求 | 重新扫描磁盘 → 更新缓存 |
| POST /api/rebuild | 强制清空缓存 → 下次请求重新扫描 |
| 服务重启 | 内存清空 → 首次请求自动重建 |

## 九、关键要点总结

| # | 要点 |
|---|------|
| ① | **内容与代码解耦**：notes/ 是内容，app/ 是代码，互不依赖 |
| ② | **内存索引 + TTL 60s**：不建数据库索引，靠内存缓存，简单高效 |
| ③ | **用户数据双写**：localStorage（即时响应）+ user_data.json（持久化+异地同步） |
| ④ | **AI 记忆 SQLite WAL**：全量保留不截断，重启不丢，发给 LLM 取最近 50 条 |
| ⑤ | **双后端容灾**：Hermes 优先（有 tool_call + 共享记忆），pcl 兜底 |
| ⑥ | **SPA Hash 路由**：前端 7 个页面，后端托管 dist/ 静态文件 |
| ⑦ | **原子写入**：user_data.json 用 tmp→bak→rename 确保不损坏 |
| ⑧ | **服务重启自动恢复**：索引自动重建、记忆从 SQLite 恢复、用户数据从 JSON 加载 |
