────────────────────────────────────────────
需求概述
────────────────────────────────────────────
现有 studyPlan（动态学习计划）和 recommendPath（学习路径）是两次独立 AI 调用，互不感知，
导致计划可能挑出路径顺序靠后的笔记（顺序打架）。参考原型 prototype-study-path-linkage.html，
本次改造实现双向闭环：
- 方向 A（路径→计划）：计划任务必须取自路径"下一个未完成步骤"，顺序由代码决定，
  AI 只负责把步骤拆解成具体笔记
- 方向 B（计划→路径）：任务标记完成后，对应路径步骤进度自动推进，步骤内任务全部完成时
  步骤自动变绿（done）
一句话：路径是唯一事实来源，计划是它的投影，完成动作回流路径。

关键规则：
- pathStepId：任务与步骤的强关联，服务端注入，AI 永远不接触这个字段
- source: "path" | "manual"：手动添加的任务 pathStepId 为 null，完成后不推进路径
- 步骤进度、路径总进度、今日/明日时间桶全部是派生计算，禁止落库——比如"步骤 2 完成 1/3"
  = 遍历 daily+tomorrow+weekly 中该 pathStepId 的任务统计得出（R13：GET 端点在 deepcopy 上算）
- 旧 studyPlan 存量 items 不做相似度迁移，直接随旧计划归档进 history（避免误对齐，R 简化）

步骤状态机
- pending    --(该步骤首个任务被调度进 daily)--> in_progress
- in_progress --(该步骤任务全部 done/skipped 且至少一个 done)--> done   [R12]
- done       --(撤销任一关联任务)--> in_progress

────────────────────────────────────────────
计划生成流程（核心改造点）
────────────────────────────────────────────
0. 无 recommendPath（或 steps 空 / 全 done）→ 返回 ok=False + 引导信息，
   前端显示"生成学习路径并创建计划"引导卡（R4）
1. 代码取未完成步骤队列（steps 按 order 排序，过滤 status=done）
2. 切片：今日 = 队列[0]，明日 = 队列[1]，本周 = 队列[:5] 的任务总量截断 5 篇（R9）
3. AI 拆解：把单个步骤标题 + 步骤自身笔记 + 候选未读笔记列表给 AI，挑 1-3 篇
4. 校验 noteId 必须来自候选集，非法即整步骤走规则降级
5. 服务端注入 pathStepId（AI 输出里没有这个字段）
6. AI 不可用（含 _chat_with_fallback 返回 error / 抛异常）→ 规则降级（R11）：
   步骤自身笔记优先（若未读）+ 标题分词关键词匹配未读笔记名补充，共 ≤2 篇；
   任何一步走了降级 → 响应 degraded: true，前端提示"规则模式，顺序仍正确"
7. 生成前先 _archive_daily_to_history 归档旧 daily（R5）
8. monthly 由 _build_monthly 从本周笔记分类派生（R8），currentCount 复用 _fill_monthly_current

def generate_study_plan_linked(notes, user_data, goal="", feedback=""):
    path = ud.get("recommendPath") or {}
    steps = sorted(path.get("steps", []), key=order)
    pending = [s for s in steps if s.get("status") != "done"]
    if not pending: return {"ok": False, "error": "路径不存在或已全部完成，请先生成学习路径"}
    today_step, tomorrow_step = pending[0], (pending[1] if len(pending)>1 else None)
    week_steps = pending[:5]

    degraded = False
    def split_step(step):                      # AI 只拆解，不选步骤
        prompt = 小 prompt：步骤标题 + 步骤自身笔记 + 未读候选 50 条 + 上次反馈
        r = _chat_with_fallback([...], temperature=0.3, max_tokens=800)
        if "error" not in r:                   # [R1] 不是 r.get("ok")
            data = _safe_json(r["content"])
            校验 items 全部 noteId ∈ 未读集 → 返回
        degraded = True; return None
    def rule_split(step):                      # [R11] 规则降级
        自身笔记优先（未读时）+ 标题分词关键词匹配，≤2 篇
    def build_items(step):                     # 服务端注入 pathStepId
        raw = split_step(step) or rule_split(step)
        return [{**i, noteName, pathStepId: step["id"], source: "path",
                 status: "pending", doneAt: None} for i in raw]

    _archive_daily_to_history(旧 plan)         # [R5]
    plan = { version:2, goal, lastUpdated, lastUpdatedBy,
             daily: {date: today, items: build_items(today_step)},
             tomorrow: {date: 明天, items: build_items(tomorrow_step)},
             weekly: {weekStart: 本周一, items: flatten(build_items 各步)[:5]},   # [R9]
             monthly: _build_monthly(notes, ud, 本周笔记),                        # [R8]
             history: 旧 history }
    if today_step.status == "pending": today_step["status"] = "in_progress"
    return {"ok": True, "plan": plan, "path": path, "degraded": degraded}

回流端点（方向 B 核心，幂等、可撤销）
POST /agent/study-plan/feedback  {noteId, action, feedback}
    action: done / undo / skip / hard / easy / feedback
    - done：已是 done → noop 返回；否则 status=done, doneAt=now
    - undo：status=pending, doneAt=None
    - skip：status="skipped"                                              [R7]
    - hard/easy/feedback：只写 item.feedback 文本，status 不动            [R7]
    - 找到任务后：若 pathStepId 且 source != "manual" → _sync_step_status
    - save_user_data；返回 {ok, plan, path}

def _sync_step_status(plan, path, step_id):
    tasks = 三时间桶中该 pathStepId 的全部任务
    resolved = [t for t in tasks if t.status in ("done","skipped")]
    if tasks and len(resolved)==len(tasks) and any(t.status=="done"):  step="done"    # [R12]
    elif any(t.status=="done"):                                        step="in_progress"
    else: step = "pending" if 旧 status != "done" else "in_progress"

def normalize_recommend_path(ai_result, prev_path):
    prev_done = {(s.noteId, s.title) for s in 旧 steps if done}
    steps = [{"id": f"step-{i:03d}", "noteId": st.note_id, "title": st.note_name,
              "order": i, "status": "done" if 迁移命中 else "pending",
              "reason": st.reason, "estimatedHours": st.estimated_hours}
             for i, st in enumerate(ai_result["path"], 1)]

            "steps": steps, "milestones": ..., "gaps": ..., "lastUpdated": now}

核心判定标准：无论 AI 返回什么，daily.items 里出现任何 pathStepId 指向非队首未完成步骤的
任务，即为实现错误——顺序选择只存在于代码里。

────────────────────────────────────────────
核心原则
────────────────────────────────────────────
- 路径是唯一事实来源：步骤状态只存 recommendPath 一份，计划是投影，进度全部现算不落盘
- 顺序决策归代码，拆解决策归 AI：AI 只做"步骤→笔记"的拆解，永远不接触 pathStepId
- 完成必须回流：done → 步骤推进；支持 undo 回退；重复 done 幂等 no-op
- manual 隔离：手动任务不推进路径，UI 有视觉区分
- AI 不可用不阻塞：降级为规则匹配（步骤自身笔记 + 关键词），顺序保证不丢
- 过期手动刷新：保持既有机制（主动点），不自动调 AI

不要改的
- 不改现有 chat 功能
- 不改 build_core.py（只用 build_index 拿笔记列表）
- 不改 db.py（studyPlan/recommendPath 都存 user_data.json，不进 SQLite）
- 不改 recommend_path 的 AI 生成 prompt（只在其输出上后处理注入字段）
- 不改 monthly 分类进度统计逻辑（_fill_monthly_current 原样复用）
- 不改 LearningPathPage / AgentPage 现有渲染（响应只增字段不删字段）
